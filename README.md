# Gonzo · אפליקציית ניהול

אפליקציית ניהול לעסק: סיכומי מכירות שבועיים, שעתי עבודה יומי ועלות עבודה, דוחות ביטולים, תחזית ותכנון משמרות, הוצאות ויומן משמרת. כל דוח ניתן לייצוא ל-Excel.

## הפעלה

דרוש Node.js 20 ומעלה.

```bash
npm install
npm run demo      # אופציונלי: טוען 4 שבועות של נתוני דוגמה
npm start         # http://localhost:3000
```

הגדרות סביבה:

| משתנה | משמעות |
|---|---|
| `APP_PASSWORD` | סיסמת כניסה. **חובה** אם האפליקציה נגישה מהאינטרנט |
| `PORT` | פורט (ברירת מחדל 3000) |
| `HOST` | `0.0.0.0` כדי לאפשר גישה מטלפון באותה רשת או מהענן (ברירת מחדל: רק מהמחשב עצמו) |
| `DATA_DIR` | תיקיית מסד הנתונים (ברירת מחדל `./data`) |

כל הנתונים נשמרים בקובץ אחד: `data/gonzo.db` (SQLite). כדי לגבות, מעתיקים את הקובץ הזה.

## מה יש באפליקציה

| מסך | מה רואים |
|---|---|
| **לוח בקרה** | מכירות, הזמנות, ממוצע להזמנה, שעות ועלות עבודה, % עבודה מהמכירות, מכירות לשעת עבודה, ביטולים. כל מדד מושווה לתקופה הקודמת. מופיעות גם התראות אוטומטיות |
| **מכירות** | פילוח לפי מקור (קופה / אתר / וולט...), לפי שעה, לפי יום בשבוע, ערוצים, אמצעי תשלום, פריטים וקטגוריות מובילים |
| **שעות ועלות עבודה** | שעתי יומי, לפי עובד, לפי תפקיד, רשימת כל המשמרות, וזיהוי משמרות חריגות (מעל 12 שעות) |
| **ביטולים** | לפי יום, עובד, סיבה ופריט, ורשימה מלאה |
| **תחזית ותכנון משמרות** | מכירות צפויות לשבוע הבא לפי ממוצע 8 שבועות, תקציב עבודה ושעות מומלצות ליום |
| **ייבוא דוחות** | העלאת CSV או Excel עם זיהוי עמודות אוטומטי (עברית ואנגלית), תצוגה מקדימה, היסטוריה ומחיקה |
| **עובדים** | שכר לשעה ותפקיד. עובדים נוספים אוטומטית מדוח המשמרות |
| **הוצאות** | חשבוניות ספקים לפי קטגוריה, Prime cost ורווח גולמי משוער |
| **יומן משמרת** | הערה יומית, ספירת קופה, מזג אוויר או אירועים |
| **הגדרות** | מע״מ, יעד % עבודה, מקדם עלות מעביד, יעד מכירות שבועי, סף התראת ביטולים |

### מלאי ופחת

| מסך | מה עושים בו |
|---|---|
| **🔢 ספירת מלאי** | סופרים במוצאי שבת, ישר מהטלפון: רשימת מוצרים לפי קטגוריה, כפתורי +/−, חיפוש, מד התקדמות והכמות מהספירה הקודמת. טיוטה נשמרת בטלפון תוך כדי, כך ששום דבר לא הולך לאיבוד. אפשר גם להעלות קובץ ספירה |
| **קבלת סחורה** | מזינים את מה שהגיע ביום שני, ידנית או מקובץ חשבונית (Excel/CSV). "מילוי לפי הזמנה מומלצת" ממלא את מה שחסר עד המלאי הרצוי |
| **מוצרים** | מוצרי מלאי, יחידת מידה, ספק, מחיר ומלאי רצוי. המחיר מתעדכן מכל קבלת סחורה |
| **מתכונים** | כמה מכל מוצר נכנס בכל מנה. רשימת המנות מגיעה מדוח "מכירות לפי פריט" |
| **צריכה ופחת** | הדוח לתקופה שבין שתי ספירות |

**החישוב לכל מוצר, בין ספירה לספירה:**
- **שימוש בפועל** = ספירה קודמת + סחורה שהתקבלה − ספירה נוכחית
- **נמכר** = כמות מכל מנה שנמכרה (מביקום) × הכמות במתכון
- **פחת / חוסר** = שימוש בפועל − נמכר, ביחידות, באחוזים וב-₪
- גם: עלות מזון בפועל מול תיאורטית (% מהמכירות נטו), שווי מלאי, הזמנה מומלצת ומגמה לפי שבועות

ספירה של שבת בלילה כוללת את המכירות של אותה שבת. כדי שהחישוב יהיה נכון צריך לייבא כל שבוע גם את דוח "מכירות לפי פריט" מביקום. המערכת מתריעה כשהוא חסר, וגם על מנות שנמכרו בלי מתכון.

### איך מחושב מה

- **עלות עבודה** = שעות × שכר לשעה × מקדם עלות מעביד (ברירת מחדל 1.25). אם בדוח המשמרות יש עמודת עלות, משתמשים בה כמו שהיא.
- **% עבודה** = עלות עבודה ÷ מכירות **ללא מע״מ**.
- **העלאה חוזרת** של קובץ מחליפה את הנתונים מאותו מקור באותו טווח תאריכים, כך שאין כפילויות. אפשר לבטל את זה בתיבת הסימון.

## העבודה השבועית

1. מייצאים מביקום את דוח המכירות היומי (Z), דוח מכירות לפי פריט ודוח ביטולים, לשבוע האחרון, כ-Excel.
2. מייצאים מהאתר את רשימת ההזמנות לשבוע.
3. מייצאים מאפליקציית המשמרות את דוח הנוכחות (כניסה / יציאה).
4. מעלים את כל הקבצים במסך "ייבוא דוחות". הסוג מזוהה לבד.
5. בלוח הבקרה לוחצים "שבוע קודם" ואז "Excel" כדי לקבל סיכום מוכן לשליחה.

אפשר גם לייבא משורת הפקודה, כדי לאטמט את התהליך:

```bash
npm run import -- ~/Downloads/z-report.xlsx --source beecomm
npm run import -- ~/Downloads/attendance.csv --source shift
```

## חיבורים אוטומטיים (מסך "חיבורים אוטומטיים")

לביקום (Beecomm) אין API ציבורי פתוח, ולכן העבודה מתחלקת לשני שלבים.

### שלב 1: ייבוא אוטומטי מהמייל (פעיל)

ביקום יכולה לשלוח דוחות יומיים במייל כל לילה אחרי ה-Z. האפליקציה בודקת תיבת דואר, מוצאת את המיילים האלה ומייבאת:
- **קבצים מצורפים** מסוג Excel או CSV. הסוג (מכירות / פריטים / ביטולים / משמרות) מזוהה אוטומטית.
- **טבלאות בגוף המייל**, אם הדוח מגיע כטבלה ולא כקובץ.
- **PDF** עדיין לא נתמך. נוסיף תמיכה אם זה הפורמט שביקום שולחת.

כל מייל מטופל פעם אחת, לפי Message-ID. המייל המקורי נשמר ב-`data/mail/`, כך שאפשר ללחוץ "עיבוד מחדש" אחרי שיפור הזיהוי.

**הגדרה (פעם אחת):**
1. פותחים תיבת Gmail ייעודית, למשל `gonzo.reports@gmail.com`, ומבקשים מביקום לשלוח אליה את הדוח היומי. אפשר גם להגדיר העברה אוטומטית מהמייל הקיים.
2. בחשבון Google: מפעילים אימות דו-שלבי, ואז יוצרים **App password**: Google Account → Security → App passwords.
3. מפעילים את השרת עם משתני הסביבה:
   ```bash
   IMAP_HOST=imap.gmail.com IMAP_USER=gonzo.reports@gmail.com IMAP_PASSWORD="xxxx xxxx xxxx xxxx" npm start
   ```
4. במסך "חיבורים אוטומטיים": לוחצים "בדיקת חיבור", ממלאים את סינון השולח (למשל `beecomm`), מסמנים "בדיקה אוטומטית" ושומרים.

| משתנה | משמעות |
|---|---|
| `IMAP_HOST` | שרת הדואר (Gmail: `imap.gmail.com`, Outlook: `outlook.office365.com`) |
| `IMAP_USER` | כתובת המייל |
| `IMAP_PASSWORD` | ב-Gmail זו סיסמת אפליקציה, לא הסיסמה הרגילה |
| `IMAP_PORT` / `IMAP_TLS` | ברירת מחדל 993 / true |

הסיסמה נשמרת רק במשתני הסביבה של השרת ולא במסד הנתונים.

**בדיקת מייל לדוגמה:** שומרים מייל כקובץ `.eml` וגוררים אותו למסך החיבורים. המערכת מראה מה היא מזהה בלי לשמור כלום, ואז אפשר לייבא. יש דוגמה ב-`sample-data/sample-beecomm-email.eml`.

**בלי שרת שרץ כל הזמן:** אפשר להריץ את הבדיקה מ-cron או מ-Task Scheduler:
```bash
npm run sync -- email
node scripts/sync.js email --eml message.eml --dry-run   # בדיקת קובץ מייל בודד
```

### שלב 2: API של ביקום (ממתין לביקום)

מבקשים מהתמיכה של ביקום **גישת API / ממשק לחברה חיצונית לדוחות מכירות, פריטים וביטולים**. כשתגיע הגישה, ממלאים את `fetchDay()` ב-`server/connectors/beecomm-api.js` ומגדירים את `BEECOMM_API_URL` ואת `BEECOMM_API_KEY`. שני המחברים שומרים תחת אותו מקור (`beecomm`), וכל ייבוא מחליף את הנתונים של אותם תאריכים. לכן המעבר מהמייל ל-API לא יוצר כפילויות.

### למה לא "רובוט" שמתחבר לביקום עם שם משתמש וסיסמה?
זה אפשרי טכנית, אבל כנראה מפר את תנאי השימוש, נשבר בכל שינוי באתר שלהם, ודורש לשמור את סיסמת הניהול של הקופה בשרת.

### הוספת מחבר חדש
כל מחבר נמצא ב-`server/connectors/` ומייצא `{ id, label, configured(), account(), sync(db) }`. נרשמים ב-`server/connectors/index.js`. התזמון, יומן הריצות ומסך החיבורים עובדים אוטומטית.

## מבנה הקוד

```
server/
  app.js         API (Express)
  db.js          סכמת SQLite והגדרות ברירת מחדל
  importers.js   קריאת CSV/XLSX, זיהוי עמודות, נרמול ושמירה
  connectors/    מחברים אוטומטיים: מייל (IMAP), API של ביקום, תזמון
  reports.js     כל החישובים והדוחות
  export.js      ייצוא Excel
  auth.js        סיסמת כניסה
public/          ממשק (HTML/JS, RTL, Chart.js)
scripts/         ייבוא משורת פקודה ויצירת נתוני דוגמה
test/            בדיקות
```
